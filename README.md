# pre-estimation

产品设计前的改造工作量评估技能，基于需求文字描述和实际项目代码分析，输出包含设计流程图和可视化工作量明细的 HTML 报告。

## 定位

面向**产品设计阶段**的工作量预评估。在产品经理/业务方提出需求后、正式设计前，快速评估开发人力投入，帮助技术决策和资源规划。

与开发实施期的工作量评估相比，本技能面向更上游的阶段，以功能模块为粒度提供粗粒度估算，输出为适合汇报用的可视化报告。

## 适用场景

- 产品经理/业务方提出需求后，设计前评估开发工作量
- 技术方案评审前的快速人力评估
- 多端（前端+后端）项目的整体工作量预估
- 需要向上汇报用的可视化工作量报告

## 前置条件

| 条件 | 必需 | 说明 |
|------|------|------|
| 需求文字描述 | **是** | 描述业务意图和功能期望 |
| 前端项目路径 | 按需 | 涉及前端改造时必须提供，本地绝对路径 |
| 后端项目路径 | 按需 | 涉及后端改造时必须提供，本地绝对路径 |
| 目标总人天 | 否 | 可作为参考，不强制凑数 |
| 设计流程图描述 | 否 | 用户可描述期望的流程；未提供则基于代码分析自动生成 |

## 工作流程

1. **需求澄清与项目确认** — 判断涉及哪些端，确认项目路径
2. **全局代码扫描** — 搜索关键业务词，定位相关模块，分析现有实现
3. **改造点分析与工时估算** — 基于实际代码逐项分析改造点，区分新增/复用/扩展，给出人天估算
4. **用户确认** — 展示评估摘要，等待用户确认范围和工时
5. **生成 HTML 报告** — 输出包含流程图、工作量明细、汇总与风险提示的可视化报告

## HTML 报告内容

报告包含四个核心区域：

- **报告头部** — 需求名称、评估日期、涉及项目、总人天汇总
- **设计流程图** — Mermaid.js 渲染的业务流程图，标注新增/改造模块
- **工作量明细** — 按端分组，列出功能模块、改造内容、改造类型、开发人天
- **汇总与风险提示** — 前后端人天汇总、关键风险点和建议

## 核心原则

- **结合项目实际** — 每个改造点基于真实代码分析，不凭空估算
- **编码前思考** — 先理解现有设计意图，再判断改造方式
- **简洁优先** — 优先复用已有模块，不过度设计抽象层
- **精准修改** — 明确每个改造点的边界和影响范围，不顺手重构
- **目标驱动执行** — 每个改造点描述可验证的产出标准

## 安全规则

- 报告中不暴露服务器地址、内网 IP、数据库连接信息
- 不展示具体代码实现细节
- 不包含 Git 提交历史中的敏感信息
- 文件名和路径做脱敏处理
